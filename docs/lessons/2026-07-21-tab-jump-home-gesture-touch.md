# 교훈 — "탭 튐"의 진짜 원인은 홈 제스처 중 탭바 스침(터치)이었다 (2026-07-21, mac mini)

## 한 줄
복귀 시 탭이 엉뚱하게 바뀌던 버그의 근본 원인은 **`@SceneStorage` 상태복원도, 앱전환기 스냅샷 버그도 아니고**,
**홈으로 나가려 화면 하단을 쓸어 올릴 때 손가락이 하단 탭바 버튼을 스치며 그 탭이 선택되던 것**이었다.
애플 버그도 TabView 오용도 아닌 **정상적인 시스템 동작**(제스처 확정 직전까지 터치가 앱에 전달됨) + 하단 탭바 조합의 UX 엣지.

## 증상
- 다른 앱 갔다 **복귀하면 탭이 튐**. 목적지는 매번 다름(특정 탭 아님).
- 07-20에 `@State → @SceneStorage`로 바꾼 "수정"이 안 먹혔음.

## 어떻게 좁혔나 (진단 오버레이 + 실기기 A/B)
디버거 없는 실사용 조건에서 화면 상단 오버레이에 tab/scenePhase 변화를 찍어(프로세스 죽어도 유지되게
UserDefaults 로그) 판독. **⌘R 디버거는 상태복원/타이밍을 바꿀 수 있어 쓰지 않음**(성능 교훈과 동일 원칙).

1. **튀는 시점 = 항상 `active→inactive`(나가는 순간)**, 복귀 시점이 아님. → "복원 문제" 가설 폐기.
2. 코드 전체에 `tab`을 `.archive/.settings`로 쓰는 곳 **없음**. → 우리 코드가 쓰는 게 아님(프레임워크/시스템).
3. **관측된 튐 5건 전부 "오른쪽"으로** 이동(특히 정보량 있는 2건은 맨 오른쪽 settings). → 랜덤 아티팩트로는
   설명 안 됨. **"오른손 엄지로 하단 오른쪽을 쓸어 올린다"**는 물리적 위치와 정합.
4. **결정적 A/B(나가는 방법을 바꿔가며):**

   | 나가는 법 | 백그라운드(스냅샷) | 하단 터치 | 튐 |
   |---|---|---|---|
   | 오른손 홈스와이프 | ✅ | ✅(오른쪽) | **튐(오른쪽)** |
   | 왼손 홈스와이프 | ✅ | 애매(왼쪽) | 안 튐 |
   | 톱 제어센터 | ❌(inactive까지만) | ❌ | 안 튐 |
   | **전원 버튼** | ✅ | ❌ | **안 튐** |

   **1행 vs 4행**이 결정타: 둘 다 백그라운드로 내려가 **스냅샷은 똑같이 찍힘**. 유일한 차이는 **하단 터치**.
   터치 있으면 튀고 없으면 안 튐 → **스냅샷 무죄, 터치가 필요조건.**

## 왜 우리 `onChange` 가드는 되는데 `Binding` setter 가드는 안 됐나
- 처음엔 `TabView(selection:)`에 **가드 바인딩**(setter에서 `scenePhase == .active`일 때만 write 통과)을 시도 → **실패**.
  setter는 TabView 내부 업데이트 도중(mid-render) 실행되어 그 시점 캡처된 `scenePhase`가 아직 `.active`였음.
- 반면 **`.onChange(of:)`는 상태가 모두 확정된 뒤** 실행되어, 나가는 순간의 우발적 선택은 이미 `phase != .active`로 관측됨.
  → **가드는 setter가 아니라 onChange에서 걸어야 신뢰할 수 있다.**

## 수정 (우회가 아니라 정석 대응)
시스템 제스처 중 들어오는 우발적 터치는 **원천 차단 불가**. 그래서 사용자가 실제로 머물던 탭을 지키는 방식:
- `@State stableTab` = **scene이 `.active`일 때 일어난 탭 변경만** 기억(진짜 사용자 선택).
- `onChange(of: tab)`에서 `.active`가 아닌데 `stableTab`과 달라지면 = 우발적 선택 → **화면 밖일 때 즉시 원복**.
- `onChange(of: scenePhase)`에서 복귀 시(`→active`) 한 번 더 보강 원복.
- 원복은 **`Transaction.disablesAnimations`로 무애니메이션** → 인디케이터 슬라이드가 눈에 안 보임.
  (첫 시도는 복귀 시에만 원복 → 인디케이터가 오른쪽→왼쪽으로 슬라이드하는 게 보였음. 나가는 즉시 원복 + 무애니메이션으로 해결.)

코드: `native/Sources/App/RootView.swift` (`stableTab`, `setTabNoAnimation`, `onChange` 두 곳).

## 일반 원칙 (다음에도 적용)
1. **"복원 시 이상"으로 보이는 상태 버그도, 실제 변경 시점은 다를 수 있다** — 시점을 로그로 먼저 못박아라.
2. **원인 후보를 A/B로 가른다** — "터치 vs 스냅샷"처럼, 변수 하나만 다른 두 조작을 같은 조건에서 비교(추측 금지).
3. **SwiftUI에서 상태 확정 타이밍이 중요하면 `Binding` setter가 아니라 `onChange`에서 판단**(setter는 mid-render라 환경값이 stale일 수 있음).
4. **의도치 않은 상태 변경의 "정석 대응"은 원천 차단이 안 될 때 "사용자 의도 상태로 복원"** — 단, 사용자에게 보이지 않게(무애니메이션/화면 밖).
