## 실기기 확인 목록을 파일로 남김 — 어제 사라진 것의 재구성

**이번 문제의 원인이 "목록을 대화에만 두고 파일로 안 남긴 것"이었다.** 어제 세션이 참조한 12건 번호 목록
("11번", "나머지 9건")은 **저장소에 없다** — worklog의 요약 한 줄과 번호 참조만 남고 세션과 함께 사라졌다.
→ `docs/native/date-roles-verify-checklist.md` 신설(커밋 5개에서 **재구성**).
**번호는 어제 worklog의 "11번" 등과 대응하지 않는다** — 어제의 11번(자동분류 규칙 1 효과)은 그 파일의 **B-8**이다.
어제 확인 완료된 3건도 A절에 무엇을 어느 경로로 봤는지 적었고, **A-3(미루기)은 경로 기록이 없다는 사실을 그대로** 남겼다
(그래서 스와이프·상세 두 경로가 B-3·B-4로 둘 다 남아 있다). 앞으로는 항목마다 `확인: 날짜 · 기기 · 경로` 칸을 채운다.

**C절(그날만 볼 수 있는 케이스)을 짜다 발견한 것 — 어제 확인 뒤 폰에서 날짜가 다시 편집됐다.**
기억에 남은 값으로 케이스를 적으면 틀리므로 실데이터 이벤트 이력을 직접 읽어 잡았다(`inbox-iphone-4532.md`):
- 「이사 계획 논의」 — `07-30 23:27 set due=2026-08-03 resurface=2026-08-02` → `23:28 set resurface=2026-07-31`.
  복귀일은 오늘 그대로지만 **배지는 D-1이 아니라 D-3**(A-3 당시 마감은 `08-01`이었다).
- 「T 우주 가입도 다시 검토」 — `07-30 23:18 set due=2026-08-07 resurface=2026-08-01`.
  어제 미룬 `08-06`이 아니라 **08-01에 돌아오고**, 마감이 미래로 옮겨져 **"지난 마감을 미뤘는데 여유 있어
  보이면 안 된다"는 케이스 자체가 없어졌다**(배지 D-6이 정상). 그 불변식의 그물은 코어 테스트에만 있고
  실데이터 사례는 자연히 생길 때까지 기다린다 — 테스트 데이터는 만들지 않는다.
→ 교훈 하나 더: **시한 있는 케이스는 값을 기억에서 쓰지 말고 그때 실데이터에서 다시 읽는다.**
