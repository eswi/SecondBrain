## 6. ⚠️ D-3에서 나온 것 — "사소"가 아니었다 (정본 §5 미결로 올림)
체크리스트가 D-3을 "사소, 거짓말 방지 확인"이라 적어뒀는데, under-claim이 **표시만 되돌리는 게 아니라 버튼·행동까지
되돌린다.** 헤드리스로 계측하고 정본 §5 미결에 기록했다(임시 probe 테스트는 계측 후 삭제 — 200 통과 유지).
- **(a) 회차 데이터 유실** — 버튼이 돌아오니 다시 누를 수 있고, 그러면 회차가 **또** 전진한다
  (`completionAdvance`의 `pivot = max(now, 마감)`은 마감이 이미 미래여도 1회차 더 전진).
  **계측: 마감 08-05 → 1차 완료 08-06 → 2차 완료 08-07.** 하루가 조용히 사라진다.
  → **8시 약을 7시 30분에 먹고 누른 뒤 상세를 다시 열어 또 누르면 내일 약이 목록·알림 양쪽에서 없어진다.**
  자동완성 `none`(약)이라 catch-up도 안 되돌린다. **이 설계의 출발점인 바로 그 경우다.**
- **(b) 무를 수 없음** — `취소`는 `cycleDoneLocal`일 때만 그려져 다시 연 화면에선 이른 완료를 되돌릴 길이 없다
  (§5의 "완료 취소 = 토글" 결정이 이 경우엔 성립하지 않는다).
- §5의 옛 괄호("이른 완료는 under-claim할 수 있으나 거짓 완료보다 안전")가 **값을 너무 싸게 매겼다**고 표시.
- **안 고쳤다 — "완료"의 정의를 건드리므로 §5 결정 사항.** 후보 3개만 적어둠:
  ① `doneThisCycle`을 **현재 회차 창 안**으로(이른 완료도 "했다"로 인정 — 셋 다 덮지만 정의를 바꿈)
  ② **재완료만 멱등**(같은 회차면 전진 안 함 — (a)만) ③ **`취소`를 판정과 분리**(`lastDone` 있으면 항상 — (b)만)
