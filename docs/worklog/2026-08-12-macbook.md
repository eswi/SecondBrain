### ③에 보탠 것 — 이름 대신 UDID

`build-sim-target.md`의 「이름으로 지정(이식성 있음)」을 **지우고** UDID 지정으로 바꿨다.
**근거는 실패 양상이 반대라는 것**(2026-08-12 실측):

| 방식 | 틀렸을 때 |
|---|---|
| `name=` | 같은 이름이 둘이면 **빌드가 되면서** 엉뚱한 시뮬로 간다 (2026-08-11 맥미니에서 걸림) |
| `id=<UDID>` | **`EXIT=64`로 죽고 쓸 수 있는 목적지 목록을 출력**한다 |

**조용히 틀리는 것보다 시끄럽게 죽는 것이 안전하다.** 옛 문장을 남기면 두 지침이 갈리므로 지웠다.
UDID는 시뮬을 지웠다 다시 만들면 바뀌는데, 그때는 위 에러가 나므로 **에러가 출력한 목록에서 받아 고친다.**
(런타임 삭제로 `unavailable`이 되는 경우엔 UDID가 유지된다 — 이 맥북의 고아 `3070E3C3`이 그 예.)
⚠️ **이 맥북엔 `unavailable` 고아 `iPhone 16 Pro (3070E3C3)`가 있다** — 런타임을 다시 깔면 이름이 둘이 된다.
`simctl erase`가 UDID를 유지하는지는 **확인하지 않았으므로 적지 않았다.**

## 4. Dynamic Type 9단계 실측 — 도구로 처음 완주

**착수 전에 규칙·교훈·도구 소스를 먼저 읽었다**(`CLAUDE.md` 「계측 규칙」 6조항 ·
`docs/lessons/2026-08-12-measure-then-use.md` · `measure-text.swift`/`measure-ui.swift` 전문).

**조건:** iPhone 16 Pro 시뮬(`ED17E1A9`) · 402×874pt @3x · 「B2 구역 기둥 옆」(`type: parking`,
표시 이름 **「주차 위치」** = 계측 최악값) 상세 화면 · **펼침 상태**.
`content_size`를 CLI로 바꾸고 스크린샷을 `measure-ui.swift`로 쟀다. **화면을 여는 것과 판정은 사용자가 했다.**

### 접힘 (표준 4단계)

| 단계 | 성역 | 분류 | 밑변 차이 |
|---|---|---|---|
| Large | 95.0 | 95.0 | **0** |
| XL | 102.3 | 102.3 | **0** |
| XXL | 109.3 | 109.3 | **0** |
| XXXL | 116.3 | 116.3 | **0** |

**네 단계 모두 위·아래가 픽셀 단위로 동일**하다. 성역 안 3열(600·620·640)과 분류 안 3열(1050·1060·1065)이
서로 일치했고, **두 카드 사이 빈틈(770·780·790)과 바깥 여백(30·1180)이 배경**으로 확인돼 별개 카드임도 확인.

### 펼침 (9단계)

| 단계 | 성역 | 분류 | 밑변 차이 | 좌우 여백 | 글자 잘림 |
|---|---|---|---|---|---|
| Large | 141.7 | 124.7 | 17.0 | 약 17pt | 없음 |
| XL | 153.7 | 130.0 | 23.7 | 유지 | 없음 |
| XXL | 185.3 | 134.7 | 50.7 | 유지 | 없음 |
| **XXXL** | 199.0 | 139.3 | 59.6 | **0** | 없음 |
| **AX1** | 225.3 | 150.0 | 75.3 | 0 | **왼쪽 잘림 시작** |
| **AX2** | 260.0 | 161.0 | 99.0 | 0 | **「주차 위」** |
| AX3 | 301.0 | 176.3 | 124.6 | 0 | 「주차」 |
| AX4 | 340.0 | 190.7 | 149.3 | 0 | 심함 |
| **AX5** | **못 쟴 (≥381)** | 204.7 | **못 냄** | 0 | **「주ㅊ」** |

### 물은 넷의 답

1. **「주차 위치」가 처음 잘리는 단계 = AX2**(accessibility-large). AX1까지 온전.
2. **좌우 여백은 두 단계로 무너진다** — XXL까지 유지 → **XXXL에서 0**(카드가 화면 끝에 붙지만 글자는 안 잘림)
   → **AX1부터 넘쳐서 글자까지 잘린다**(왼쪽 아이콘·첫 글자부터).
3. **접힘 밑변은 표준 넷에서 전부 0pt.** ⚠️ **AX 단계의 접힘은 재지 않았다**(펼침 하나만 훑기로 정함).
   **안 한 것이므로 「AX에서도 0pt」라고 말할 수 없다.**
4. **상세 화면으로 안 보이게 되는 단계는 없다.** AX5까지도 「기억」 제목·두 카드·탭바로 알아볼 수 있다.
   다만 **AX3부터는 양쪽이 잘려 읽기가 사실상 불가능**하다.

### 한 줄

**성역이 2.8배(141.7→393 이상) 자라는 동안 분류는 1.6배(124.7→204.7)만 자란다.**
벌어지는 원인은 분류가 못 따라가는 게 아니라 **성역이 혼자 커지는 것**이고,
가장 큰 한 방은 **XXL에서 「이 값은 어떤 편집으로도 바뀌지 않아요」가 두 줄로 넘어가는 것**이다
(그 구간만 +31.6pt, 다른 구간은 +12~14pt). **사용자가 스크린샷 두 장을 보고 판정했다.**

### ★ 좌우 여백 — 시스템이 아니라 `DetailView` 것이다

| 화면 | XXXL에서 좌우 여백 |
|---|---|
| 설정 | 약 **17pt 유지** (x=40 없음 / x=55 있음 · x=1145 있음 / x=1160 없음) |
| 새로운 기억 | 약 **11pt 유지** (x=25 없음 / x=35 있음 · x=1175 있음 / x=1185 없음) |
| **상세(`DetailView`)** | **0pt** — x=5·x=1200에도 카드가 있다 |

**같은 XXXL에서 두 화면은 지키고 상세만 잃는다.** 시스템이 여백을 줄이는 것이라면 셋 다 줄어야 한다.
코드와도 맞는다 — `DetailView.swift:167`의 `.padding(16)`은 **고정 리터럴**이고 저장소에 `ScaledMetric`이
하나도 없다. **여백이 준 게 아니라 내용이 밀고 넘친 것**이다.
구조: `ScrollView { VStack{…}.padding(16) }`에서 **VStack 폭 = 가장 넓은 자식**. 자식 하나의 최소 폭이
쓸 수 있는 370pt를 넘으면 VStack이 넓어지고, `card()`가 전부 `maxWidth:.infinity`라 **나머지 카드도 같이**
넓어진다. 그래서 한 행이 아니라 **세 행 전부**가 동시에 여백을 잃었다.
`ScrollView`는 세로 전용이라 **가로 초과분은 스크롤되지 않고 클립된다.**
**→ 목록 화면은 멀쩡하므로 고칠 범위는 `DetailView` 한 곳이다.**

### ★ 걸린 함정 넷 — 어제의 넷은 안 났고, 새 넷이 났다

넷 다 **「나온 값을 읽는 법」**이 틀린 것이었다. 전문은 `native/tools/measure-ui.swift` 머리주석에 넣었다.

| | 무엇 | 신호 |
|---|---|---|
| ⑤ 모서리 | 둥근 모서리 안쪽 열로 재서 짧게 읽음 | 열마다 값이 조금씩 다름(92.3/93.7/94.3/95.0) |
| ⑥ 배경 뒤바뀜 | XXXL에서 카드가 화면 끝까지 붙어 기본 배경 표본(x=15)이 카드 안에 들어감 | **글자를 키웠는데 원문 카드가 88.0→40.0pt로 줄었다** |
| ⑦ `--bg`를 카드 위에 | ⑥을 고치려다 배경 점을 카드 표면에 찍음 | 출력 밝기 0.1127(카드). 배경은 0.0744 |
| ⑧ **창 끝을 카드 끝으로** | `--y`에서 잘린 구간을 카드 높이로 적음 | 구간 끝값 == `--y` 끝값 |

**⑧이 가장 나빴다 — 「못 잰 것」을 「잰 것」으로 적었다.**
AX5 성역을 **「≈393pt」** 로 적었는데, 실제로는 **하단 바에 가려 밑변이 화면에 없어 잴 수 없는** 카드였다.
말할 수 있는 것은 **「최소 381pt 이상」** 뿐이다.

**어떻게 잡았나 — 사용자가 「AX4·AX5가 화면에서 너무 커 보였다」며 재계측을 지시했다.**
다시 재보니 성역 구간이 이미지 맨 아래(2621px)까지 끊기지 않았다 —
**카드 → 하단 바 → 탭바가 배경 없이 붙어 있어 어디가 카드 끝인지 갈라낼 수 없다.**
AX4는 다섯 열이 340.0pt로, 네 열이 190.7pt로 일치해 **앞 값이 맞았음이 확인**됐고, AX3도 유효하다
(구간이 1756에서 끝나고 그 뒤가 배경). **AX5만 못 잰다.**

**규칙 ④(「결론은 실측으로 닫는다」)를 지켰다고 생각한 자리에서 ⑧이 났다** —
화면을 잰 것은 맞는데 **잰 값이 유효한지를 안 봤다.**

### 도구 주석에서 고친 것 — 「글자 없는 열을 골라야 한다」는 틀렸다

`measure-ui.swift` 원주석의 그 문장은 사실이 아니다. **글자·아이콘은 배경과 밝기가 달라 카드로 셈되어
구간을 안 쪼갠다.** 진짜 문제는 ⓐ **이웃 요소와 이어붙는 것**(다이내믹 아일랜드·하단 바 → `--y`를 좁힌다)
ⓑ **카드 안의 어두운 박스**(원문 입력칸처럼 배경과 밝기가 비슷한 것은 구간을 끊는다).
**오늘 세 번째 「문서와 실제가 갈린 자리」다.**

## 6. 별개 과제로 넘긴 것 (오늘 고치지 않는다)

1. **`DetailView` 가로 넘침** — 남은 질문은 **「어느 자식이 넘치게 하는가」**.
   스크린샷은 잘린 뒤의 화면이라 **최소 폭을 잴 수 없다.** 코드를 만져야 답이 나온다.
   후보: 줄바꿈이 안 되는 「2026-07-18 18:20」·「iPhone 16 Pro」. **계산으로 좁히는 것은 규칙 ④가 막는 자리.**
2. **화면마다 여백값이 제각각** — 설정 17 / 새로운 기억 11 / 상세 16pt.
3. **XXXL 홈에서 숫자 타일 「살아있는 기억」이 「살아있는…」으로 잘림.**
4. **AX 단계의 접힘 밑변 미측정** — 표준 넷만 0pt 확인. AX는 안 쟀다.

## 7. 꺾쇠 방향 — 사용자가 실제로 반대로 읽었다

**2026-08-12, 사용자가 `⌃`를 보고 「접힘」이라고 두 번 말했다.** 실제 화면은 펼침이었다
(성역 199.0 / 분류 139.3pt = 펼침 값 · 「음성」 줄 · 「주차 위치」 글자 · 두 줄 안내문이 모두 있었다).
이 앱은 `⌃`를 **「지금 펼쳐져 있으니 누르면 접힌다」**로 쓰는데, 사용자는 **`⌃` = 접힌 상태**로 읽었다.

**화면 기호는 사용자가 정할 사안이므로 건드리지 않았다**(「항시 규칙」 6). 판단만 남겨둔다 —
나중에 볼 때 **「사용자가 실제로 반대로 읽은 적이 있다」가 근거가 된다.**
숫자로 갈렸기에 계측이 안 틀어졌다. 화면 상태를 말로만 주고받았다면 **펼침 값을 접힘 표에 적었을 것이다.**
