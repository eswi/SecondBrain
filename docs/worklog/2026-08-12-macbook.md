## 8. ★ ③(미검증 상수)이 닫혔다 — 계측하러 간 자리가 아닌데 나왔다

**어제 ③은 「Dynamic Type 크기를 기억으로 썼다」였다**(XXXL을 20pt로 — 실제 23pt).
그 뒤 「L 17 / XL 19 / XXL 21 / XXXL 23」은 **공표 표를 쓴 값이고 실측이 아니다**로 남아 있었다.

**오늘 닫혔다. 그런데 이걸 재러 간 것이 아니었다.**
확인 목록 8번(「펼침은 이름만 84.8 / 90(XXXL)이어야 한다」)을 닫으려고 **「주차 위치」 글자 폭**을 쟀는데,
세 값의 **비율**에서 보였다:

| 단계 | 글자 폭 (픽셀 실측) | 비율 | 폰트 비 |
|---|---|---|---|
| Large | **60.0pt** | — | 17 |
| XXL | **74.0pt** | 74.0/60.0 = **1.233** | 21/17 = 1.235 |
| XXXL | **81.0pt** | 81.0/60.0 = **1.350** | 23/17 = 1.353 |

코드가 `Text(m.label).font(.body)`로 **`.body`를 명시**하고(`DetailView.swift:628`) `.body`는 Large에서 17pt다.
**따라서 「XXL = 21pt · XXXL = 23pt」가 공표 표가 아니라 화면에서 확인된 값이 됐다.**
**계산을 한 줄도 안 쓰고 렌더만으로 닫혔다** — 오늘 「나(렌더 실측)로 간다」고 정한 것의 값이 여기서 나왔다.

⚠️ **`XL 19`는 여전히 안 쟀다.** 그 단계의 글자 폭을 재지 않았으므로 공표 표 값 그대로다.

### 편향의 방향이 반대다 — 반드시 구분할 것

`measure-text.swift` 계산값은 17/21/23pt에서 **63.2 / 77.6 / 84.8**pt다.
픽셀 실측(60.0 / 74.0 / 81.0)보다 **일정하게 3.2~3.8pt 크다.**
(픽셀 쪽이 양끝 안티에일리어싱을 놓쳐 덜 잡는 계통 오차로 보인다 — 방향이 한쪽이고 크기가 일정하다.)

| 대상 | 계산 vs 실측 |
|---|---|
| 카드·블록 **높이** | 계산이 **2~3pt 작다**(낙관적) — 여유를 깎아 읽어야 한다 |
| **글자 폭** | 계산이 **3.2~3.8pt 크다**(보수적) — 계산값을 그대로 쓰는 쪽이 안전하다 |

**안 적어두면 「계산은 낙관적이니 깎아 읽어라」를 글자 폭에 잘못 적용한다.**
`measure-text.swift` 머리주석과 `CLAUDE.md` 「계측 규칙」 6에 넣었다.

### 8번의 나머지 반쪽은 못 닫았다

「84.8 / 90」의 **90(칸 폭)** 을 재려던 시도가 실패했다 — 세 단계 모두 카드 오른쪽 끝이 **이미지 끝(1206px)까지**
검출됐는데, 접힘 계측에서 Large의 x=1180이 배경이었던 것과 모순된다. **믿을 수 없는 값이라 적지 않는다.**
확실한 것은 **XXXL까지 실제로 안 잘린다**는 것뿐이다.

⚠️ **가설(단정하지 않음):** XXXL에서는 **가로 넘침 때문에 카드가 원래보다 넓어져 있다.**
그러면 「XXXL에서 안 잘린 것」이 **넘침 덕**이었을 수 있다. 넘침을 고치면 칸이 좁아져 다시 빠듯해질 수 있다.
→ **별개 과제 ①에 붙임: 넘침을 고친 뒤 「주차 위치」가 XXXL에서 여전히 안 잘리는지 다시 볼 것.**
칸 폭은 그때 같이 잰다(그때 칸이 바뀌므로 지금 재도 다시 재야 한다).

## 9. ★ 오늘 네 번째 — 이번엔 시간이었다

**어시스턴트가 「지금 14:12」·「14:15」·「14:47」이라고 말했는데 전부 잰 값이 아니라 추정이었다.**

**→ 「계측 규칙」이 화면 치수만 다루고 있었다.** 같은 실수가 **시간·개수**에서도 난다.
그래서 조항을 넓혔다 — **`CLAUDE.md` 「계측 규칙」 #7 신설:**

> **「잰 값」과 「짐작한 값」을 같은 말투로 말하지 않는다. 화면 치수만이 아니라 말하게 되는 모든 수 —
> 시간·개수·소요시간을 포함한다.** 시간을 말할 때는 **그때마다 `date`를 읽는다.**
> 앞서 읽은 시각에 「이만큼 걸렸겠지」를 **더하지 않는다.** 짐작이면 **「추정」이라 붙인다.**

### 이 오판이 계획을 바꿨다

18:04에 알았을 때 **F-3(20:15)까지 2시간 10분**이었다. 원래 계획(B2 = EXIF GPS JPEG 생성·심기 +

## 13. 확인 목록 5·17 — 5는 통과, **17은 XL에서 깨진다**

### 5번 — 아이콘 접힘 30 ↔ 펼침 44 ✅

「B2 구역 기둥 옆」 · Large · 분류 아이콘(자동차)의 **실제 그려진 크기**를 접힘/펼침에서 쟀다.

| | 접힘 | 펼침 | 비율 |
|---|---|---|---|
| 아이콘 **세로** | **27.3pt** | **40.0pt** | **1.465** |
| 아이콘 가로 | 33.7pt | 50.3pt | 1.493 |

**기대 비율 44/30 = 1.467.** 세로가 **1.465** — 사실상 일치한다(가로 1.493은 열 간격 5px = 1.67pt 해상도 안).
교차 확인: **글자높이/폰트크기 비**가 27.3/30 = **0.910**, 40.0/44 = **0.909**로 맞는다 —
두 상태가 같은 심볼을 크기만 바꿔 그린다는 뜻이다.
**「+ 이름으로 바뀌나」도 확인** — 펼침에 「주차 위치」가 나타나고 접힘엔 없다.
⚠️ **「프레임 40」은 못 쟀다** — 틀은 화면에 안 보인다. 글자 27.3pt가 그 안에 있다는 것까지만.

**오는 길에 함정 ⑧에 두 번 걸렸고 둘 다 「값이 기대와 어긋난다」로 잡았다:**
ⓐ 열 범위가 좁아 펼침 아이콘의 **바깥 바퀴**를 놓쳐 비율이 1.256으로 나왔다(펼침이 1.47배 넓으니 열도 넓어야 한다).
ⓑ y창이 「분류」 라벨을 물어 펼침 세로가 **760 = 창 시작값**으로 나왔다.
→ 그래서 **창 끝에 닿았는지를 출력에 직접 찍게** 했다(`✅ 창 안`). 오늘 만든 판별법을 실제로 쓴 자리다.

### ★ 17번 — Large에서만 안 넘친다. **XL부터 깨진다**

「세금 관련 서류 훑어보기」(미기억 · `임시` 배지) 상세.

**Large 실측:**

| | 값 |
|---|---|
| 제목 줄 내용 (「분류」+「임시」 배지+`⌄`) | **88.3pt** (x 846~1110) |
| 분류 카드 | 119.0pt (x 800~1156) |
| 안쪽 칸 (패딩 14×2) | **91.0pt** |
| **여유** | **2.7pt** |

기록의 **「~82 / 90pt로 빠듯하다」** 와 대면 **칸(90 ↔ 91.0)은 맞았고 내용이 82 → 실측 88.3pt**로
**6.3pt 더 크다. 예상보다 더 빠듯했다.**

**그리고 한 단계만 올리면 무너진다:**

| 단계 | 「임시」 배지 |
|---|---|
| **Large** | 「임시」 한 줄 ✅ (여유 2.7pt) |
| **XL** | **「임」/「시」 두 줄로 쪼개짐** ❌ |
| **XXL** | **「⋯」로 뭉개짐** ❌ — **글자가 사라진다** |

**→ 17번의 답: 「Large에서는 안 넘치지만 XL부터 깨진다.」**
XXL에서는 **배지가 무슨 말인지 화면에서 알 수 없다** — 「임시」라는 뜻이 사라진다.
확인 목록이 「빠듯하다」고 적어둔 걱정이 **실제였고, 임계가 바로 다음 단계**였다.

> ⚠️ **편향에 대한 관찰 하나 더(단정 아님).** 오늘 「주차 위치」 **글자 폭**에서는 계산이 실측보다
> **크게**(보수적) 나왔는데, 여기 **조립 합계**(「분류」+배지+접기 표시+간격)에서는 82 → 88.3으로
> 계산이 **작게**(낙관적) 나왔다. **조립은 낙관적, 순수 글자 폭은 보수적**으로 보인다 —
> 어제 ①(조립에서 간격을 한 번만 셈)과 결이 같다. **표본이 적으므로 관찰로만 남긴다.**

6. **★ 미기억 항목의 「임시」 배지가 XL에서 깨진다** — XL에서 「임」/「시」 두 줄, XXL에서 「⋯」.

## 15. ✅ F-3 통과 — G-7이 끝났다 (2026-08-12 20:2x)

**사용자가 집에 가기 전 회사에서 봤다.** 20:15을 조금 넘겨 **20:2x**에 확인 —
창이 **20:00~23:55**이라 문제없다(그 시점 마감까지 **3시간 30분** 남아 있었다).
**앱을 완전히 종료했다 다시 열고** 봤다(기록에 있던 그 단계).

**대상:** 「나 - 정시 완료 시험」 — **주기가 「매주」**인 것을 확인하고 열었다.
(이름이 같은 `70942905`는 **매일**이라 대상이 아니다. 가리는 기준이 실제로 쓰였다.)

| | 본 것 | 판정 |
|---|---|---|
| ① | '지금 챙길 것'에 **떴다** | ✅ 미리 알림 20:00이 지나 게시됨 |
| ② | **「완료」 칩이 없다.** 대신 **`D-DAY` 칩 + 「3시간 남음」**이 우측에 두 줄 | ✅ **판정선 통과** |
| ③ | 상세 버튼이 **`[이번 것 했어요]`** — **누르지 않았다** | ✅ |

### ⚠️ 「D-DAY 칩」이 어긋나 보였고, 코드로 갈랐다

기록에는 통과 화면이 **「칩 없음 + `[이번 것 했어요]`」**로 적혀 있었는데 화면에는 **칩이 있었다**(`D-DAY`).
**표면적으로 어긋나 보이는 자리라 기입 전에 코드에서 확인했다:**

- **`D-DAY`** = `DDayBadge`(`Components.swift:12` — `case .today: return "D-DAY"`) — **마감이 오늘**이면 뜬다.
  마감이 **08-12 23:55**이므로 **정상**이다.
- **「완료」 칩** = `Components.swift:140` — `Recurrence.doneThisCycle(it, now:)`가 **참일 때만** 뜬다.
  **이것이 F-3의 판정선**이고, **없었다.**

**둘은 완전히 별개 배지다.** 기록의 「칩 없음」은 **「완료」 칩**을 가리킨 것이라 어긋나지 않는다.
→ **기록 문구가 좁았던 자리다.** 다음에 같은 것을 적을 때는 **「'완료' 칩이 없다」**로 어느 칩인지 적는다.

### 왜 이것이 판정선이었나

저장값(08-06 이후 무변경): `lastDone 08-06 01:02` · `lastDoneDue 08-12 23:55` · **`recur=weekly`**.
옛 판정 `lastDone ≥ 직전 회차` — **매주라 직전 회차 = 08-05 23:55** → `08-06 01:02 ≥ 08-05 23:55` = **참**
→ **옛 코드는 「완료」 칩을 달았을 자리다.** 새 판정은 3절(미게시)에서 끊겨 false.
**값이 갈리는 자리였고, 새 코드가 옳게 갈랐다.**

**앱은 08-10 빌드 그대로다** — F-3을 위해 오늘 아무것도 설치하지 않았다(「F-3 전 설치 금지」를 지켰다).
그 금지는 **이제 해제됐다.**
