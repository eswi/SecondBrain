### 3-1. ⛔⛔ 뿌리 하나가 셋을 만들고 있었다 — **`onAppear`·`onDisappear`가 「열림·닫힘」이 아니다**

`UIImagePickerController`는 **`.fullScreen` 모달**이라 뜨는 순간 밑에 있는 호스팅 컨트롤러에
`viewDidDisappear`가 가고 닫힐 때 `viewDidAppear`가 간다 → SwiftUI가 그것을
**`onDisappear`/`onAppear`로 그대로 흘린다.**

| 언제 | 무엇이 돌았나 | 무엇을 잃었나 |
|---|---|---|
| 카메라가 **열릴 때** | `speech.cancelAndDiscard()` | **녹음한 원본 음성 파일** · 먼저 붙인 사진 |
| 카메라가 **닫힐 때** | `speech.start()` → `transcript = ""` | **받아쓰기한 글** |

★★ **신고보다 한 겹 더 나빴다.** 사용자는 *"저장되어 있던 내용들이 사라짐"*(=글)을 봤는데,
**같은 콜백이 음성 원본 파일까지 지우고 있었다** — 화면에 안 보이는 손실이라 **아무도 못 봤다.**
⛔ **「글이 사라진다」만 고쳤으면 음성 손실은 남았을 것이다** — 원인을 짚은 값이 여기서 났다.

✅ **표시 둘로 갈랐다:** `didStart`(시작은 **한 번만**) · `cameraOpen`(**덮는 동안은 종료가 아니다**).
✅ `SystemCamera.present`에 **`onFinish`**를 더했다 — **찍든 취소하든 못 띄웠든 한 번** 온다.
⛔ **못 띄운 경우에도 부른다** — 안 부르면 표시가 `true`로 남아 **임시 파일이 샌다.**
★ **그리고 정리를 [취소] 버튼이 직접 하게 했다** — 수명 콜백에만 맡기면 이렇게 조용히 어긋난다.

⛔ **음성 원본 파일이 안 지워지는 것은 이 판정에 안 들어 있다** — 화면에 안 보이는 것이라
사용자가 볼 수 없다. **①이 통과했으므로 같은 콜백을 타던 그것도 안 돌았다고 볼 수 있지만,
그것은 추론이고 잰 것이 아니다.** 재려면 `devicectl … copy from`으로 폰의 임시 폴더를
가져와 봐야 한다(CLAUDE.md ⓒ) — **안 했다.**

## 6. 안 한 것 · 물을 것

- ⛔ **푸시 안 했다** — 종료 절차 2(사용자 지시 후).
- ⛔ **사양서 반영 안 했다** — 이번 변경 중 사양서에 닿는 것은 **[저장]의 다음 화면**과
  **새 녹음의 단락 구분**이다. **§3-4의 물음이 풀린 뒤에 함께 올리는 것이 맞다**(그때 값이 바뀔 수 있다).
  ⚠️ **항시 규칙 2는 그대로 열려 있다** — 다음 세션이 이 줄을 보고 묻는다.
- ⛔ **[저장] 버튼 문구를 안 바꿨다** — 사용자는 「[ 저장하기 ]」로 적었는데 앱의 말은 **「저장」**이다.
  **화면 문구는 사용자가 정한다**(항시 규칙 6).
- ⏸ **`MediaAddSheet`·`DetailView` 쪽 카메라 입구는 같은 손실이 없다** — 확인했다:
  `DetailView`에는 `onAppear`·`onDisappear` 정리가 **아예 없다**(grep 0건). **뿌리는 수집 시트 하나였다.**

> ⚠️ **세션이 자정을 넘었다** — 날짜는 08-31이지만 **같은 세션**이라 여기 적는다
> (08-28 worklog가 08-29 새벽 작업을 담은 것과 같은 형태).

## 7-1. 사용자 지시와 결과

*"지금 상세화면에서 '보조 자료' 카드가 매우 훌륭하게 잘 만들어졌어. 그래서 '수집 화면'의
사진 찍기 인터페이스를 없애고 '보조 자료' 카드를 추가하자. 텍스트 화면은 높이를 절반 정도로
줄이고 그 아래에 자료 카드를 붙이는 것으로 하자."*

| 무엇 | 어떻게 | 판정 |
|---|---|---|
| 「사진 찍기」 줄 제거 → **카드** | `CaptureMediaCard`(신설) · 껍데기는 **`MediaStrip`**으로 갈라내 상세 카드와 **함께 쓴다** | ✅ *"카드가 나왔고…"* |
| 텍스트 칸 **160 → 80pt** | `minHeight`(시작 높이만 줄었다) | ✅ *"적당해 줄었어. 일단 이 크기 좋아."* ⚠️ **재검토 예정** |
| 여러 개 붙는다 | 사진·URL 둘 다 | ✅ *"둘 다 여러개 등록 잘되고"* |
| 길게 눌러 **「지우기」** | `contextMenu` + **이미 있는 말** | ✅ *"삭제까지 해봤어. 잘 돼."* |
| 저장 뒤 상세 카드에 그대로 | 자료가 **op**으로 붙는다 | ✅ *"저장뒤에서 똑같이 보였어"* |
| 짧게 눌러 크게 보기 | `ZoomableImage` | ⏸ **못 잼** |

## 7-2. ★★ **[저장] → 상세**를 **세 번** 틀렸다 — 왕복을 남긴다

| 판 | 무엇을 했나 | 무엇이 났나 |
|---|---|---|
| `06aff97` | 닫힘 뒤 **350ms 지연**(`Task.sleep`) | ✅ 통과 — **자료가 없었을 때만** |
| `22d62ad` | 같은 코드 + 자료 카드 | ⛔ [저장]이 자료마다 `load()`를 돌려 겹쳤다 → 밀기가 **반쪽만 적용**, 내비 바에 **`‹` 자국**만 남았다(**둘로 보였다**) |
| `821ea01` | **아예 걷어냈다** | ⛔ **내가 사용자 말을 잘못 읽었다** — *"그건 괜찮아. 유지하자"*는 **「그 순서는 괜찮다」**였고 기능을 버리라는 뜻이 아니었다 |
| `78a4362` | **`onDismiss`로 옮겼다**(시간 짐작 제거) | ⛔ **여전히 안 됐다** — 타이밍은 고쳤고 **원인을 놓쳤다** |
| **`8251d53`** | **「찾을 때까지 기다린다」**(`resolveAfterWrite`) | ✅ **통과** |

### ★★ 진짜 원인 — **`load()`가 비동기다**

`append(_:)`는 파일에 한 줄 붙이고 `load()`를 부르는데 그것이
**`func load() { Task { await reload() } }`** 다. 그래서 `capture` 직후
**`model.current(newId)`가 nil**이고, 밀기 코드가
`guard let item = model.current(id) else { return }`로 **조용히 지나갔다.**

★★ **그리고 이것이 `06aff97`의 350ms가 실제로 하던 일이었다.**
그때 나는 그 지연을 **「시트 닫힘을 기다린다」**로 주석에 적었는데, **기다린 것은 이 재로딩**이었다.
⛔ **그 오해 때문에 `onDismiss`로 옮기며 대기를 함께 잃었다.**
⚠️⚠️ **주석이 틀린 이유를 적고 있으면, 그것을 근거로 다음 수정이 빗나간다** —
`78a4362`가 정확히 그렇게 났다. **「무엇을 기다리는가」를 주석에 적을 때는 재서 적는다.**

### ⛔ 한 번 `await reload()`하는 것으로도 부족했다
`reload()`는 `loadGen`으로 **그사이 더 최신 로드가 시작되면 자기 결과를 버린다.**
저장 경로는 **자료마다** `load()`를 부른다(사진 N · URL M · `addURL`의 미리보기 Task) →
**재로딩이 여럿 겹친다.** → **그래서 「몇 번」·「몇 초」가 아니라 「찾을 때까지」로 기다린다.**
⚠️ **`Task.sleep`이 없다**(`reload()`가 실제 파일 I/O라 반복 자체가 시간을 쓴다).

## 7-3. ⛔ 성역 축이 바뀌었다 — **정본 훑기가 밀려 있다**

정본 §6 10번이 *"⛔ 여기서 정하지 않는다"*로 남겨 둔 자리를 **사용자가 정했다: 자료는 전부 op.**
- ⛔ **안 고른 것:** create 블록 화이트리스트를 접두어로 여는 것(§3-W-4 1번).
- ✅ **고른 것:** **op** — §3-Y-1 결정 2와 **같은 모양**. 성역에 남는 자료는 **녹음 원본 `audio` 하나**.
- ⚠️ **대가:** 「수집 당시 함께 들어온 사진」이라는 보장이 **데이터에서 사라진다**(알고 골랐다).
- **`PhotoStore.finalize`는 호출자가 0이 됐지만 지우지 않았다** — 옛 파일 이름 꼴(`<id>.jpg`)의
  근거가 코드에서 사라진다. `AudioStore.finalize`와 짝으로 남기고 ⛔ 주석을 붙였다.

⛔ **훑어야 한다** — 신호 ②(배타적 분기의 소속이 바뀐다: create → op)에 걸린다.
**대상:** `media-expansion-design.md` §6·§3-W-4·2071줄 근처 · `photo-capture-design.md` ·
`edit-policy.md` §6 · 사양서. **고치기 전에 목록으로 보고한다**(정본 훑기 규칙 6).
