## 6. ★★ 오늘의 진짜 소득 — 사용자가 걸린 자리

### 코드에서 확인한 구조

| 사실 | 근거 |
|---|---|

| 접기는 **두 카드가 함께** 움직인다 | 사진 하나 보려고 **분류 카드까지** 펼쳐진다 |

### 뜻 — ③이 「하면 좋은 것」에서 「걸린 것」이 됐다

**2차 압축이 만든 것이 아니다.** 사진이 성역 안에 있는 것은 그 전부터였고, 압축은 **접힘을 기본으로** 만들어
그 어긋남을 **드러냈을** 뿐이다. 어긋남 자체는 의미 쪽이다 —
**성역 = 「어떤 편집으로도 안 바뀌는 것」**(보관), **사진 = 「보려고 있는 것」**(열람). 성격이 다른 둘이 한 카드에 있다.

**코드가 이미 이 방향을 예고해 뒀다:**
- `DetailView.swift:251` — *"2단계로 사진·지도가 「수집 원본 자료」로 빠지면 빈칸이 499 → 48pt로 줄어든다"*
- `DetailView.swift:299` — *"이 카드를 접고 나중에 사진·지도를 「수집 원본 자료」로 떼어내면…"*

**차이는 근거의 종류다.** 그때는 **계산**(빈칸 pt)이었고, 지금은 **실사용에서 걸렸다.**

⚠️ **여기서 설계하지 않는다**(항시 규칙 1 — 사양서 우선·즉흥 금지). 방향은 사양서/Claude 챗에서 받는다.
⚠️ **새 자리의 화면 이름은 사용자가 정한다**(항시 규칙 6). 「수집 원본 자료」는 **작업용 이름이지 화면 문구가 아니다.**

| `감기약 먹기 시험용…` (`90D927B2`) | – | **✅** | – | – | – | **1** |

**계산 근거** (`Recurrence.missed` · `ItemSchedule.overdueHidden` · `isPublished`):
- **놓침** = 마감부터 오늘 자정 전까지의 회차 수. 꺼둠이면 `now` 대신 **꺼둔 시점**까지만 센다.
  복약 08-13−08-04=**9** · E-4 08-13−08-06=**7** · 감기약은 꺼둔 08-04가 마감 08-09보다 **앞**이라 **0**.
- **회차 시각 없음** = `due`가 없어야 한다. 셋 다 `due`가 있다 → 안 뜬다.
- **늦었는데 숨겨짐** = `overdueHidden`. 셋 다 막힌다:
  - 감기약 → 조건 1 `isDormant`(꺼둠)에서 바로 nil
  - 복약 → 미리 알림이 **없어** `isPublished`가 마감 분기로 가고 `마감 ≤ now`라 **게시됨** → nil
  - E-4 → 미리 알림 08-06 00:02가 **이미 지나** 게시됨 → nil
- **미리 알림 당김** = `recurLeadClamped` 필드. 셋 다 비어 있다.

### ★ 배너들은 설계상 상당수가 서로 배타적이다

| 짝 | 겹치나 |
|---|---|
| 놓침 ↔ 회차 시각 없음 | ⛔ **배타** — `due` 유무로 갈린다 |
| 꺼둠 ↔ 늦었는데 숨겨짐 | ⛔ **배타** — `overdueHidden` 조건 1이 `isDormant`를 먼저 막는다 |
| 꺼둠 ↔ 놓침 | ✅ **겹칠 수 있다** — **꺼두기 전에 이미 쌓여 있었으면** |
| 놓침 ↔ 늦었는데 숨겨짐 | ✅ 겹칠 수 있다 — 마감 과거 + 미리 알림 **미래** |

→ **「한 항목에서 다섯을 다 본다」는 애초에 불가능하다.** 배너를 많이 보려면 **항목을 여러 개** 봐야 한다.

### 실데이터 전체에서 둘이 겹치는 항목은 하나뿐이다

**`약 먹기 시험용  E-6`(`5ACEA309`) — 꺼둠 + 3일 놓침.**
마감 08-02, 꺼둔 시각 08-05 00:47 → 꺼두기 전에 3회차가 지나 있었다.
(08-07 worklog의 「E-6 3일 놓침」과 같은 값 — 꺼둠 이후로 안 늘어난 것이 여기서도 확인된다.)

⚠️ **그런데 이것도 표본이다** — F-5가 아니라 **E-6 대상**(`recurrence-verify-checklist`: *"E-6 항목은 계속 건드리지 말 것"*).
**「표본이 아닌 것 중에」 배너가 둘 겹치는 항목은 없다.**

### 결론 — ⑤ 대상을 바꿀 이유가 없다

**⑤는 §11에서 이미 끝났다.** 비표본 넷으로 **놓침·꺼둠·회차 시각 없음 셋을 다 봤다.**
F-5 표본 셋으로 바꿔도 **얻는 것이 없다**(같은 배너를 하나씩 볼 뿐이고, 못 본 둘은 여전히 못 본다).

**★ 그러므로 F-5 표본 셋은 열지 않는다.** 위험만 있고 이득이 없다.

### ⚠️ 그래도 남길 것 — 셋 다 표본이고, 조심할 것이 같다

사용자 지적대로다: **`복약`·`E-4`·`감기약` 셋 다 F-5 폴백 표본**이고,
**보기만 하는 것은 안전하지만 누르면(완료·켜기) `lastDoneDue`가 생겨 표본이 영구히 깨진다.**
**폴백 상태는 재현할 수 없다** — 되돌리는 조작이 없다.
앞으로 이 셋이 안내에 등장하면 **그 경고를 항상 붙인다.**

## 14. ⛔ 정정 — 「복약」에 「늦었는데 숨겨짐」은 안 뜬다 (원본 op까지 확인)

**제기된 것:** *"「복약」에서 그 배너가 왜 뜨는지(마감 08-04 · **다시 보기 08-15** · 9일 늦음)도 기록할 것."*
**확인 결과: 안 뜬다. 그리고 `08-15`라는 값은 실데이터 어디에도 없다.**

`01781308`의 **모든 op를 원본에서** 훑었다(접은 결과가 아니라 파일의 줄 전부):

```
441   id: 01781308-…                       ← 항목 블록
445   set due=2026-08-03T06:00 recur=daily type=recurrence
448~453  set lastDone=…                    (여섯 줄)
456   set confirmed=true
457   set due=2026-08-03T06:00 lastDone=2026-08-03T00:11
458   set due=2026-08-04T06:00 lastDone=2026-08-03T09:19
831   set due=2026-08-04T09:00
832   set due=2026-08-04T06:00              ← 마지막
```

**`resurface`를 설정한 op가 한 줄도 없다.** 최종 상태에 **`resurface` 키 자체가 존재하지 않는다**(확인함).

### 왜 안 뜨나 — 미리 알림이 없는 것이 곧 차단 사유다

`overdueHidden`의 조건 4는 `guard !isPublished`인데, `isPublished`는
**미리 알림이 없으면 마감 분기로 내려가** 되풀이에서 `마감 ≤ now`면 **게시됨(true)** 을 낸다.
복약은 마감 08-04가 지났으므로 **게시된 상태** → 조건 4에서 nil.

**「숨겨짐」의 뜻이 그것이다** — *마감은 지났는데 **미리 알림이 아직이라 목록에 안 나오는*** 항목.
복약은 **목록에 나와 있다**(지금 챙길 것). 나와 있는 것을 「숨겨졌다」고 할 수 없다.
배너가 안 뜨는 게 **정상 동작**이고, 뜨면 그게 버그다.

두 번째 차단도 있다 — 배너는 `let on = oh.returnsOn`을 요구하는데
`gatedResurface`가 `resurface` 없으면 nil을 낸다. **돌아올 날이 없으므로 할 말도 없다.**

### 실데이터 전체를 훑었다 — 그릴 항목이 **하나도** 없다

살아있는 항목 **94개** 전부에 조건을 걸었다
(마감 있음 · 마감 ≤ 지금 · 꺼둠 아님 · **미리 알림이 미래**):

```
⛔ 없다 — 조건을 만족하는 항목이 실데이터에 하나도 없다
```

→ §3 ②의 결론이 **되풀이 18개가 아니라 전체 94개 기준으로 다시 확정됐다.**
**「늦었는데 숨겨짐」은 지금 어떤 항목을 열어도 못 본다.** 상태를 **만들어야** 한다.

### ⚠️ 두 값이 섞였다 — 「9일」은 맞고 배너는 틀리다

복약의 **「9일 놓침」은 실제로 뜬다**(마감 08-04 → 오늘 08-13). 그 **9**가 맞으므로
「9일 늦음」이라는 표현도 숫자만 보면 맞아 보인다. 그런데 **그 숫자를 쓰는 배너가 둘이다** —
`missedBanner`(뜬다)와 `overdueHiddenBanner`(안 뜬다). **같은 9가 다른 배너에 붙은 것**이다.
(코드가 그렇게 설계돼 있다: *"「얼마나 늦었나」는 날짜 단위 — 놓침과 같은 규약이라 두 숫자가 안 어긋난다."*)

**★ 남길 것: 숫자가 맞는다고 그 숫자를 쓰는 자리가 다 뜨는 것은 아니다.**
배너는 **자기 조건**으로 뜬다. 숫자의 일치는 배너 존재의 근거가 아니다.

### ⚠️ 작은 정정 — 판정 함수는 어제 만든 것이 아니다

계산에 쓴 것은 **저장소에 원래 있는 Core 함수**다 —
`ItemSchedule.overdueHidden` · `isPublished` · `gatedResurface` · `Recurrence.missed`.
오늘 새로 만든 것은 **op 로그를 접는 일회용 파이썬 스크립트**뿐이고, 스크래치패드에 있다(저장소 밖).

## 16. 폰 스크린샷으로 `measure-ui`를 돌릴 수 있나 — **된다** (조건 넷)

### ⛔ 먼저 정정 — 「B2 구역 기둥 옆」은 사진·지도를 가진 항목이 **아니다**

| 제기된 것 | 실제 |
|---|---|
| 사진·지도를 둘 다 가졌다 | ❌ **포인터 두 줄뿐**이고 **파일이 없다.** 화면엔 「원본 사진 있음 · **이 기기엔 없음**」 안내만 뜬다. 지도는 좌표가 **사진 EXIF 안에만** 있어 안 뜬다 |
| 성역 카드가 길 것이다 | ❌ **오히려 짧다.** 안내 줄 둘이 붙어도 맥북이 *"150pt 이상 남는다"* 로 기록했다 |
| (전제) 폰에서 볼 수 있다 | ❌ **폰에 그 항목 자체가 없다** — `SampleData`는 `#if DEBUG` + `targetEnvironment(simulator)` + `!hasFolder` 세 겹으로 실기기에 안 닿는다 |

맥북 §16이 정확히 이것으로 「확정 근거」를 한 번 바로잡았다 —
*"그건 시뮬 전용 샘플에서 나온 모습이라 폰에는 그 항목 자체가 없다."* **같은 자리에 두 번째로 걸렸다.**

**★ 사진·지도를 진짜로 둘 다 가진 것은 `82B1044B`(주차 위치 2026-08-11 20:45)** — 오늘 §5에서 본 그 항목이다.
**2단계 설계의 핵심 재료는 그쪽이다.**

### 도구 쪽 — 기기를 안 본다. 순수 픽셀이다

`measure-ui.swift`는 PNG를 읽어 **세로 한 열의 밝기 구간**으로 카드 경계를 찾는다.
기기 종류·출처를 묻지 않는다. `--scale` 기본값 **3**만 맞으면 된다.

**실측 (2026-08-13 01:5x):** 시뮬(iPhone 16 Pro) 스크린샷 = **1206 × 2622 px · PNG**
→ 논리 **402 × 874 pt** @3x.
**폰도 iPhone 16 Pro라 같은 값일 것으로 본다** — ⚠️ **폰 스크린샷은 아직 안 쟀다.**
**첫 장이 오면 `sips`로 확인하고 그때 「잰 값」으로 바꾼다.**

### 조건 넷

| # | 조건 | 왜 |
|---|---|---|
| 1 | **기종이 같을 것** (둘 다 iPhone 16 Pro) | 다른 모델이면 픽셀 크기·scale이 달라져 시뮬 값과 비교가 깨진다 |
| 2 | **Dynamic Type 단계를 적어둘 것** | 시뮬은 `simctl ui content_size`로 내가 맞추지만 **폰은 사용자 설정**이다. 어느 단계인지 모르면 **값을 못 쓴다**(설정 ▸ 화면 표시 및 밝기 ▸ 텍스트 크기) |
| 3 | **다크/라이트를 맞출 것** | 도구가 밝기 차로 경계를 찾는다. 주석의 기준값이 **다크 모드**다(배경 ≈0.0744 · 카드 ≈0.1127) |
| 4 | **PNG 원본으로 보낼 것** | iOS 스크린샷은 PNG. **AirDrop은 원본 보존.** ⚠️ 메신저로 보내면 **JPEG 재압축**돼 경계가 뭉갠다 |

### ★ 이것이 §8의 결론을 넓힌다 — B2 없이 2단계 계측이 열린다

§8에 *"픽셀 계측이 필요해지면 그때 다시 심는 얘기가 나온다"* 라고 적었는데, **경로가 하나 더 있었다:**
**폰 스크린샷에는 시뮬에 없는 진짜 사진·지도가 들어 있다.** 사용자가 찍어 보내면 그대로 잰다.

| | 폰 스크린샷 | 시뮬 스크린샷 |
|---|---|---|
| **진짜 사진·지도** | ✅ 있다 | ⛔ 없다(포인터뿐) |
| **Dynamic Type 단계 훑기** | ⛔ 매번 손으로 설정·촬영 | ✅ **자동**(`simctl ui content_size` 반복) |
| 자동화 | ⛔ 사용자 조작 | ✅ 전부 |

→ **상보적이다.** 진짜 사진의 실측 한 장은 **폰**에서, 단계별 회귀는 **시뮬**에서.
**B2(합성 JPEG 심기)는 여전히 취소 상태로 둔다** — 폰 한 장이 더 싸고 더 진짜다.
