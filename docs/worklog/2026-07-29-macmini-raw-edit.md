## 0단계 — 조사 (코드 무변경)
본문 수정은 새 인프라가 아니라 화면만 없는 상태였다. 근거 요약:
- 저장 경로 이미 지원: `Event.edit`(임의 필드) → `InboxModel.commitEdits`(필드 안 가림) → `EventWriter.serialize`.
- 직렬화도 준비돼 있었음: raw만 담은 edit는 create 블록(date+time+source+raw 전부 필요) 안 타고, fields.v1 JSON 편집 블록으로 감(question이 이미 이 길).
- DetailView: raw는 **완전 읽기전용**(`Text` + 자물쇠 + "준비 중"), draft에 raw 없음(§8 잠금).
- 병합: raw는 일반 콘텐츠 필드, per-field LWW. 성역 필드는 create 블록에만 쓰여 edit가 안 담으면 불변.
- 기존 테스트: create의 raw는 덮지만 **edit로 raw를 바꾸는 왕복은 0건**이었음 → A에서 신설.

## A단계 — 저장·왕복 (커밋 단위 1)

### 발견·재현한 직렬화 구멍
값이 **공백 없이 `|`를 포함**하면(`a|b`, `2026-07-31|09:00|정리`) `set raw=...` 평문 경로로 새어
`@ hlc | id | set raw=a|b` 줄이 파싱 때 `|`로 쪼개져 **`|b`가 유실**됐다. `MergeEngineTests`의
"레거시 id `|`" 함정과 동종. → 왕복 테스트(`testRawRoundtrip_pipeNoSpace_repro`)로 **먼저 재현**(`a` 만 남음) 후 고침.

### 고침 — 조건 추가가 아니라 판단을 뒤집음
`EventWriter.serialize`의 편집 직렬화를 **"위험 문자가 있으면 JSON" → "안전하다고 확신할 때만 평문, 아니면 JSON"**으로 뒤집었다.
특정 필드(raw)만이 아니라 **값 자체**로 판단. 안전 조건 = `isPlaintextSafe(_:)`:
- 앞뒤 공백 없음(파서가 `@`-조각을 trim → 잘림 방지)
- 공백·탭·줄바꿈(`\n`·`\r`)·`|` 없음
- 빈 문자열은 `set k=`로 무손실 왕복(파서 `omittingEmptySubsequences:false`)이라 **안전으로 봄**
  (미분류 되돌리기 `set type=`가 이 형태 — 기존 형태·파일 불변 유지).

## A'단계 — 직렬화 판단을 문자 목록 → 왕복 검증 (커밋 `165d7df`)
위대표 지적: `isPlaintextSafe`가 여전히 문자 열거였다(이번에 `|`를 빠뜨려 생긴 문제가 반대편으로 옮겨간 것).
실제 누락도 있었다 — 줄바꿈은 `\n`·`\r` 외 **U+000B·U+000C·U+0085·U+2028·U+2029**가 있고 Foundation의
`.newlines`·`enumerateLines`·NSRegularExpression은 이것들도 줄 경계로 본다(웹 복사 텍스트로 유입 가능).
- **고침:** 평문 후보를 만들어 **직렬화→파싱했을 때 원본 이벤트와 정확히 일치할 때만** 평문(`plaintextRoundtrips` = 최종 게이트).
  `isPlaintextSafe`는 빠른 1차 거르기로만 남김(성능). 판단이 문자 목록에 의존하지 않게 됨.
- 두 곳에서 `.newlines` **집합**으로 방어(문자 목록 아님): ① 왕복 게이트가 candidate의 단일 줄 여부 ② `compactJSON`이
  JSONSerialization이 리터럴로 남기는 `.newlines` 문자를 `\uXXXX`로 이스케이프 → fields.v1이 한 줄 유지(파서·리더가 안 쪼갬).
- 테스트 +1(U+2028·U+0085·U+000B가 평문으로 안 새고 JSON으로 왕복). Core 83→84.
