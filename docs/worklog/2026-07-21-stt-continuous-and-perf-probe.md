## 1. STT — "멈췄다 이어 말하기" (③ 조각 누적 + 사용자 정지)
- **방침**: 두 메커니즘 분리(세션 끊김 ≠ 받아쓰기 끝). `SpeechCapture.swift` 재작성.
- **핵심 버그·수정**: `SFSpeechAudioBufferRecognitionRequest`(버퍼·온디바이스)는 **짧은 침묵에 isFinal을 안 준다.**
  그래서 2~3초 침묵 시 내용이 partial에만 있다가 온디바이스 인식기가 ~3초에 가설을 리셋 → 앞 내용 소실.
  → **20fps 티커가 마지막 발화 후 1.2초 무성장이면 조각을 먼저 `committedText`에 커밋하고 request/task를 회전**
  (세그먼트 gen으로 취소된 옛 task 콜백 무시). **사용자 확인: 리셋 문제 해결됨.**
- **침묵 진행 막대**: 받아쓰기 네모 위 가로 막대(왼→오), 새 발화면 0 리셋, 75%↑ 경고색, 자동종료 0이면 숨김.
- **자동 종료 설정**(`SpeechSettings.swift`): `sttAutoStopSeconds` 기본 7, 0=끄기([완료]로만), 범위 0…30. 설정 "음성" 섹션.
- **크래시 수정**: `engine.inputNode`(탭 설치)를 `engine.prepare()/start()` **앞**으로 — 노드 없이 start하면
  `AVAudioEngineGraph Initialize (inputNode != nullptr…)` assertion 크래시.

## 2. 비동기 로드 (InboxModel·RootView)
- `load()`의 파일 I/O(`readFragments`)를 `Task.detached`로 **메인 밖**으로. 결과 반영만 메인(loadGen 가드로 낡은 결과 버림).
- 초기 자동분류는 `.task { await model.reload(); autoClassify() }`로 로드 후 트리거.
- **주의**: 이건 성능 "버그 수정"이라기보다 **콜드 iCloud에서 메인 블로킹 방지용 방어 개선**. 원인이 아래 설치 페널티로 밝혀졌으므로, 원치 않으면 되돌려도 됨(해는 없음).

## 3. 성능 조사 (첫 실행 30s · STT '듣는 중' 10s) — **미해결 이슈 (열어둠)**
> **결론 내리지 않음.** 아래는 정황일 뿐. 내일 **① 실기기에서 재설치-첫실행 vs 재실행 속도 직접 비교**부터.
> 차이가 크면 설치 페널티 가설 채택, 차이가 없으면(=재실행도 느리면) 가설 기각하고 다시 판다.
- **계측(`sbTime`, 지금은 제거)으로 실측**한 결과, 모든 구간이 건강한 기기보다 5~10배 느림:
  런치(App.init→첫프레임) 5.8s · 폴더 열거(`contentsOfDirectory`+보안스코프) 2.6~4.3s · `engine.inputNode` 첫 접근 4.9s ·
  beginOnMain 앞 메인 정체 5.2s. **recognitionTask 생성은 즉시**(→온디바이스 모델 로드가 STT 지연 원인 아님).
- **베이스라인 대조**(내 이번 변경 전부 stash → 커밋 상태로 실행): **베이스라인도 똑같이 느림** → 내 세션 코드 무관.
- **실기기 A/B**: 사용자 "**재빌드 없이 앱만 다시 켜면 빠름**" → **Xcode 디버그 재설치 직후 첫 실행 페널티**로 잠정 결론
  (iOS 앱 검증·오디오/음성 콜드 초기화 최초 1회). 실사용(설치된 앱 재실행)엔 영향 없음.
- **⚠️ 미확정**: 사용자가 "깔끔하지 않다, MacBook에서 수없이 리빌드했지만 이런 적 없었다"며 **내일 MacBook에서 재현 여부 재확인**하기로. 가설이 틀리면 다시 판다.
- 교훈: 조율-읽기 → 모델-로드로 두 번 헛짚음. **계측·A/B로 바로잡음.** 추측보다 측정.
