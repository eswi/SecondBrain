## 0. 목적

**상세 화면 전체를 컴팩트하게.**

⚠️ 「원문 아래가 한 화면에 들어오는 것」은 **그 목적을 재는 지표 하나**지 목적이 아니다.
(확인표에서 G-8을 「이번 작업의 목적」으로 적었던 것을 정정했다 — 나중에 읽을 때 목적이 좁아 보이면 안 된다.)

**시작점(실측):** 「제목 줄 / 값 줄」이 칸마다 반복돼 **시간 설정 카드만 7줄 238pt**.
원문 아래 **715pt** / 볼 수 있는 세로 **694pt** → 한 화면에 안 들어왔다.

## 1. 제목은 안 줄였다 — 계측이 그렇게 답했다

한 줄에 「제목 + 값 + 시각 + 지우기 + 펼침 표시」를 넣어 재 봤다(iPhone 16 Pro **402pt**):

| 조각 | 폭 |
|---|---|
| 「미리 알림」(가장 긴 제목, .callout 16pt) | 59.5 |
| 「8월 14일」 / 「오전 11:30」(최악) | 58.9 / 69.9 |
| 「지우기」(.caption 12pt) | 31.1 |
| 간격 8×4 | 32 |
| **합** | **263pt** / 카드 안쪽 **342pt** → **여유 79pt** |

긴 제목 셋(「회차 시각」·「미리 알림」·「다시 보기」)이 전부 59.5pt로 같다. **가장 긴 것으로 재도 남으므로
제목은 손댈 이유가 없다.** — *줄여서 뜻을 흐릴 이유가 없다*(사용자).

## 2. 시간 설정 — 모양이 한 번 갈아엎혔다

**① 접이식 → ② 한 줄 + 대화상자.** 사용자가 셋을 짚어 접이식을 접었다:
1. 접힌 줄이 날짜를 말하는데 **펼치면 같은 날짜가 피커로 한 번 더** 나온다
2. 날짜는 [지우기]·[날짜 설정] **버튼**인데 **시각만 토글**이라 짝이 안 맞는다
3. 값 있는 줄을 누르는 것은 *"고치겠다"* 는 뜻인데 **펼치기가 한 단계를 더 얹는다**

```
회차 시각  지우기                      8월 14일 06:00
미리 알림  날짜 설정                   없음
              ↑ 제목 옆                     ↑ 누르면 대화상자

        ┌──── 회차 시각 (폭 400) ────┐
        │        [ 달  력 ]          │
        │ 1일 미루기 3일 미루기 7일 미루기 │  ← 결과가 위 달력에 바로
        │ 시각 [토글]      오전 6:00  │  ← 꺼도 흐리게 남음
        │    취소      │     확인     │
        └────────────────────────────┘
```

### 결정과 근거

| 결정 | 근거 |
|---|---|
| **[지우기]·[날짜 설정]을 제목 옆** | 사용자 결정. 폭이 남는다(214/342pt). 덤으로 **파괴적 버튼과 값 표적이 줄 양끝으로 갈라져** 오폭이 준다 |
| **「없음」을 눌러도 같은 자리가 열린다** | 죽은 표적을 안 만든다. 그때 **오늘 날짜를 넣고** 연다(옛 [날짜 설정]과 같은 동작 — 빈 피커를 안 만든다) |
| **미루기 1·3·7일** | `ItemSchedule.deferBy(days:)` **한 함수**. 상한·차단·알림 판정은 셋이 공유하고 **갈리는 것은 날 수 하나뿐**. 기준은 **오늘+N일**(지금 값+N일이 아니다) |
| **미루기가 자리를 안 닫는다** | 눌러 보고 다른 날 수를 누르거나 [취소]로 되돌릴 수 있어야 한다 |
| **[취소] │ [확인]** | 취소는 **열 때의 값**으로 되돌린다. `editingBackup`은 **임시층이 아니라 한 칸짜리 버퍼** — 값의 층은 여전히 draft/저장값 **둘**뿐이다 |
| **꺼둔 시각을 기억** | 안 그러면 **껐다 켜는 것만으로 6:00이 09:00으로 덮인다.** 화면이 보여주는 흐린 값과 켤 때 붙는 값은 **같은 `pendingTime`** 을 본다(갈리면 화면이 거짓말) |
| **amber = 「지금 값이 원래와 다르다」** | 줄의 값 글자·미루기 버튼이 **같은 `changes`** 를 본다. 하단 「저장하지 않은 수정이 있어요」와 **같은 색**이라 「있다 ↔ 어디」가 한 쌍 |
| **달력 tint는 평소 accent** | `.tint`가 **월 이동 < > 까지** 물들여 시끄러웠다. **딱 한 경우만 amber** — 「없음」이었다가 날짜가 생겼을 때(어느 날이든 다 바뀐 것이고 비교할 «전»이 화면에 없다) |
| **피커에 범위(`in:`) 없음** | B(2026-08-08)에서 뺀 그 자리 — 범위가 값을 조용히 끌어당긴다 |

**★ 사양서에 남긴 것:** *"버튼이 늘어도 규칙은 하나다"*(`memory-philosophy.md` 규칙 1 절).
화면에 선택지가 늘 때 **규칙을 같이 복사하는 것이 가장 흔한 새는 자리**다 — 셋으로 복사했으면
규칙 1이 또 갈릴 때 **고칠 곳이 셋**이 되고 그중 하나를 빠뜨린다.

## 3. 반복 설정 — 한 줄 합침 (5줄 → 4줄)

```
반복 주기  매일 ⌄        자동 완성  없음 ⌄
꺼두기                              [토글]
```

**꺼두기는 계산상 못 합쳤다** — 최악값 「당일 지나면」까지 넣으면 셋이 **401pt / 342pt**로 59pt 넘친다.
제목을 「반복」·「자동」으로 줄이면 337pt로 5pt 남는데 **글자 크기 한 단계에 깨진다.**

## 4. ★ 달력 크기 변함 — 다섯 번째에 닫혔다

### 원인은 달력이 아니라 **하단 바**였다

```
날짜를 처음 누름 → dirty 켜짐 → 하단 바에 「저장하지 않은 수정이 있어요」 줄 생김
→ safeAreaInset(bottom) 커짐 → ScrollView가 쓸 수 있는 높이 줄어듦
→ 그 위 대화상자에 주어지는 높이도 줄어듦 → 달력이 「채우기」를 포기하고 제 크기로 떨어짐
```

**「색만 바뀌는데」가 아니었다** — 화면 맨 아래에 줄이 하나 생겼고 **대화상자에 가려 안 보였을 뿐**이다.
**증거:** 스크린샷 두 장 실측 — 큰 달력 쪽엔 amber 띠가 **없고**, 작은 달력 쪽엔 **y 725~740pt에 있다.**

이 하나로 셋이 다 설명된다: ⓐ 날짜를 누를 때만(그때 `dirty`가 처음 켜짐) ⓑ 한 번 작아지면 그대로
(`dirty`는 계속 켜짐) ⓒ **폭을 넓힐수록 변동이 작아짐**(«제 크기»가 «채운 크기»에 가까워 낙차가 작다).

**고침:** 대화상자를 `ignoresSafeArea()`로 **안전 영역 밖에** 놓아 하단 바와 무관하게 만들었다.

### ⚠️ 네 번 헛짚었다 — 왜 틀렸는지

| | 시도 | 왜 틀렸나 |
|---|---|---|
| 1~3 | `frame(height:330)` · `+maxHeight:.infinity` · `fixedSize(vertical:)` | **증상이 난 곳(달력)만 고쳤다.** 원인은 바깥에 있었다 |
| 4 | 폭 300→360→380 | **상관을 원인으로 봤다.** 폭은 **낙차만** 줄였다 |

> **★ 결정적 단서는 사용자 관찰이었다** — *"폭을 넓힐수록 변동이 작아져"*.
> **폭이 원인이면 그렇게 매끄럽게 비례하지 않는다.** 폭이 낙차만 줄인다는 뜻이었고,
> 그러면 **떨어뜨리는 힘이 따로 있다**는 말이 된다. 그 힘이 하단 바였다.
>
> **배운 것: 증상이 난 곳과 원인이 있는 곳이 다를 수 있다.** 세 번을 달력 안에서만 찾다 놓쳤다.

**확정:** 폭 **400pt**(칸 ≈56pt·행 ≈46pt / 폭 300일 때는 34pt). 다른 대화상자는 **그대로 300pt**
(`StandardDialog`의 `width` 기본값 — 부르는 쪽 무변경).
**글자 크기 줄이기(`dynamicTypeSize`)도 시험했다 되돌렸다** — 이 달력만 기기 글자 크기 설정을 안 따르게
되는 접근성 손해에 비해 값이 없었다.
