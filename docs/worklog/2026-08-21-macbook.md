## 11. ★★ 여덟 번째 형태 — **「있는데 찾을 방법이 없다」** (2026-08-21)

**`D6E4950B`를 찾는 데 실패한 것이 계기다.** 「삭제된 기억」에 분명히 있었고 사용자가 **첫 시도에서 못 찾았다.**
원인을 코드에서 갈랐더니 **데이터도 파서도 정상**이었다:

- `EventLog`의 `verb.hasPrefix("set ")`가 **`set type=discard`(레거시 꼴)를 제대로 읽는다.**
- `trashed = r.deleted + r.live.filter { type == "discard" }` — **목록에 확실히 들어 있다**(83줄 중 75번째).
- ⛔ **그런데 `SearchView`가 훑는 것은 `liveNonDone + doneItems`뿐이다** — **`trashed`는 검색 대상이 아니다.**

| 형태 | 어디가 막혔나 | 어느 쪽 문제 |
|---|---|---|
| **①~⑤** (08-20) | 목록에 있는데 안 열린다 / 승인된 미결로 보인다 / 목록에 없다 / 결정을 되돌린다 / 자리가 임시다 | **문서** |
| **⑥** (08-21 오전) | 이미 **한 일**이 **안 한 것**으로 적혀 있다 | **문서** |
| **⑦** (08-21 오전) | 이미 **된 일**이 **「하지 말 것」**으로 적혀 있다 | **문서** |
| **⑧** (08-21 오후) | **데이터도 파서도 정상인데 사용자가 도달할 길이 없다** | ★ **앱** |

### ★ 이것이 「있는 목록이 소진되게 한다」의 한계를 보여준다 (사용자 정리)

> **「목록을 소진한다」로는 안 잡힌다 — 확인 목록에 올리려면 먼저 도달할 수 있어야 한다.**

⛔ **①(지도 핀)과 갈린다:** 지도 핀은 **누를 자리가 있었고 눌러야 알았다.**
⑧은 **누를 자리 자체가 없다** — 아무리 눌러도 검색으로는 안 나온다.
★ **어제부터 세워온 과제(목록 소진)의 앞에 한 단계가 더 있다는 뜻이다:**
**① 도달할 수 있나 → ② 목록에 올라와 있나 → ③ 목록이 소진되나.**
어제 §20에서 ②를 앞에 붙였고(*"소진시키기 전에 목록에 올라와 있나를 먼저 센다"*),
오늘 그 앞에 ①이 붙었다.

⏸ **검색은 지금 고치지 않는다**(사용자: *"보관함 화면으로 가면 보인다"*). → `HANDOFF.md` §4에 과제로 올렸다.
⚠️ **의도인지 결함인지는 안 정했다** — 「검색은 살아있는 것만」이 설계일 수 있고,
고치면 **삭제된 것이 검색에 섞이는 것을 원하나**부터 사용자가 정해야 한다(화면 동작).
