# 음성 원본 보존 설계 — 녹음 + 저장 + 다시 듣기 (native v1)

> **정본 위치.** 이 문서는 "STT 받아쓰기와 함께 원본 음성을 녹음·보존하고 상세화면에서 다시 듣는" 기능의 설계 정본이다.
> 근거 원칙: 사양서 §0(두 층 — 텍스트=영속 자산 / 지능=소모품), §1(이미지 = `assets/` 포인터 선례), §7·§6(외부 전송 최소화·온디바이스 STT), `memory-philosophy.md`.
>
> **상태: 구현·실기기 검증 완료(2026-07-22).** 시나리오 A(단일 녹음)·B(여러 take 이어짐)·C(취소 정리) 모두 실기기 청취 확인. **1차 방식(직접 쓰기·단일 파일)이 정지→재개 경계에서 끊김·누락 없이 동작** → 포맷 일관성 리스크(§9) 이 기기에서 해소. AVAudioConverter 변환 경로는 불필요·동시성 경고로 제거(§2).

## 0. 왜 / 한 줄
STT는 불완전하다. **원본 음성이 남아 있으면** 나중에 (a) 직접 듣고 텍스트를 고치거나 (b) 더 나은 STT에 다시 맡길 수 있다.
= **"원본 미디어는 불변, 텍스트 층은 가변"** 원칙을 데이터 구조로 실제 구현하는 것. 음성이 진실의 기준(ground truth), 텍스트는 그 위의 가변 해석.

## 1. 데이터 모델 — 음성은 "최초 수집 성역"에 찍는 포인터

- **파일명 = 항목 UUID.** `InboxModel.capture()`가 이미 만드는 `UUID().uuidString`을 그대로 써 **`<uuid>.m4a`**. 항목 ↔ 음성 1:1 결정적 연결.
- **포인터 필드 = create 블록의 `audio: <uuid>.m4a`.** 이미 있는 성역 필드 `device`와 같은 자리(최초 수집에만 찍고 이후 어떤 편집도 안 건드림).
  - 파서(`EventLog`)는 create 블록의 임의 `key: value`를 이미 일반 처리 → **파싱 무변경**.
  - 직렬화(`EventWriter`)만 create-블록 화이트리스트에 **`"audio"` 1줄 추가**. (병합 로직 아님 — §6.)
  - `ResolvedItem.fields["audio"]`로 UI에 노출. create에만 있으므로 per-field LWW상 **절대 안 덮임 = 사실상 불변**.
- **포맷 = AAC / .m4a**(음성 저용량). PCM 원본은 과도.

## 2. 녹음 — 한 항목 = 한 파일, 모든 take가 시간순으로 이어짐 (핵심)

STT "이어받기"에는 두 층위가 있고, 오디오는 **둘 다를 넘어 하나의 파일로 이어져야** 한다:

1. **조각 회전(segment rotation)** — 한 녹음 세션 안에서 `request`/`task`/tap이 여러 번 재생성(isFinal·침묵 1.2초). **엔진은 계속 돌아감.**
2. **[정지]→[재개](resume)** — 엔진이 완전히 stop 후 다시 start. 텍스트는 `committedText` seed로 이어짐.

**설계: `AVAudioFile`을 "탭보다도 엔진보다도 오래" 살린다 — 수집 시트 세션 전체 동안 하나의 열린 파일.**
- 시트 열림(첫 `start()`) → 임시 파일 하나 생성 후 **계속 열어둠**.
- 조각 회전: `startSegment()`가 tap을 떼었다 다시 붙일 때, **매 tap의 콜백이 같은 열린 파일에 append**. (엔진 안 멈추므로 자연히 연속.)
- [정지]→[재개]: `stop()`은 **엔진만 멈추고 파일은 안 닫음(=일시정지)**. `resume()`이 엔진을 새로 start하고 새 tap이 **같은 파일에 계속 append**. → 앞 take 음성 보존, 뒤 take가 시간순으로 이어짐.
- 파일을 닫는 시점은 **[저장] 또는 시트 종료([취소]/dismiss)뿐.**

**즉 오디오 파일 수명 = 수집 시트 수명.** 그 안의 모든 정지/재개/조각회전은 같은 파일에 이어 쓰기(append).

**형식 일관성(구현 리스크·명시):** 엔진을 껐다 켤 때 `inputNode.outputFormat`이 이론상 달라질 수 있다(오디오 경로 변경 등). `AVAudioFile`은 생성 시 고정 포맷이라, 다른 포맷 버퍼를 그대로 쓰면 `write`가 실패한다.
- **1차 방식(구현·채택):** 첫 `start()`의 입력 포맷으로 파일 포맷을 고정하고 **직접 쓰기**만 한다. 같은 기기에서 정지→재개하면 포맷이 일치해 그대로 이어 쓴다. **실기기 검증 결과 경계 끊김·누락 없이 동작(2026-07-22).** (AVAudioConverter 변환 경로는 시도했으나 불필요 + `@Sendable` 입력 블록 동시성 경고로 제거. 재개 중 오디오 경로가 바뀌어 포맷이 달라지는 드문 경우엔 그 조각을 건너뜀 — 실기기에서 문제되면 아래 폴백.)
- **폴백(1차가 불안정하면):** 정지→재개 구간마다 세그먼트 파일을 따로 쓰고, **[저장] 때 시간순으로 이어붙여(concatenate) 하나의 `<uuid>.m4a` 생성**. 형식 차이에 더 강하나 이어붙이기(export) 단계가 붙음. (현재 미구현 — 1차가 실기기에서 충분히 동작해 유지.)
- 어느 쪽이든 **불변식은 동일**: 한 항목 = 한 파일, 모든 take 시간순.

**스레딩:** tap 콜백은 오디오 스레드에서 옴 → 파일 쓰기는 그 스레드에서만. 생성/닫기는 메인. **닫기 전 반드시 tap 제거**(in-flight 버퍼 경합 방지). `SpeechCapture`의 기존 "@unchecked Sendable·상태는 메인에서만" 규율에 맞춰 파일 핸들도 같은 규율로 다룸.

## 3. 저장 위치 · 프라이버시 · 용량

- **확정 목적지 = 기기 로컬.** 앱 샌드박스 `Application Support/SecondBrain/audio/<uuid>.m4a`.
  **그리고 iCloud에도 올린다** — `iCloud Drive/SecondBrain/audio/`. 폰의 **135개가 2026-08-20 00:14에 이관됐다.**
  - **로컬 사본은 지우지 않는다.** 확정이 쓰는 자리이자 iCloud에서 받아온 것을 두는 자리다(`media-icloud-design.md` §5).
  - **왜 iCloud로 갔나:** 폰을 잃으면 자료를 **전부** 잃었다 — 텍스트는 조각 파일로 동기화되는데 **음성·사진만 기기에 갇혀 있었다.**
  - iPhone이 수집·검토의 심장(§0-A) → "iPhone에서 녹음→iPhone에서 다시 듣기"가 여전히 주 경로다.
    **다만 Mac도 범위다** — 2026-08-20에 Mac에서 사진 보기·재생이 들어갔다(`media-icloud-design.md` §7).
  - 텍스트(진짜 자산)는 조각 파일로 **전 기기 동기화**. **음성도 이제 전 기기에서 열린다** — 다만 경로가 다르다(조각 파일이 아니라 iCloud의 자료 폴더).
- **용량:** 음성 AAC ≈ 0.25–0.5 MB/분. 메모 10–30초 ≈ 0.1–0.25 MB. 1,000개 ≈ ~100–250 MB(기기 저장, 사소).
- **다른 기기에서는** 텍스트가 먼저 보이고 **음성은 iCloud에서 받아온다.** 받는 동안 「원본 음성 받는 중…」,
  못 받으면 「아직 못 받았어요 · 다시 시도」(문구 정본 = `media-icloud-design.md` §8).
  **이 기기에도 iCloud에도 없을 때만** 「원본 음성 있음 · 이 기기엔 없음」이 뜬다(`MediaAvailability.absent`).
  - ⏸ **이 문구는 바꾸기로 정해져 있다 → 「원본 음성 있음 · 파일을 못 찾음」** (2026-08-20 사용자).
    **왜:** `absent`는 *이 기기에도 iCloud에도 없다*는 뜻인데 「이 기기엔 없음」은 **「다른 기기에서 열면 되겠네」로 읽힌다.**
    **코드 변경이라 단계 6이 아니다** — 다음 설치 때 색 정리와 함께 간다. 사진 쪽도 같은 꼴로 맞춘다.

> 「외부 전송」이 아니다** — 사양서의 「외부 전송 최소화」는 **그대로 유효하다.**
> ⚠️ **위 옛 근거 줄을 들어 iCloud를 되돌리지 말 것** — 뒤집힌 쪽이 지금이다.
> **근거·전말: `docs/native/media-icloud-design.md`.**

## 4. 다시 듣기 (재생)

- **위치 = 상세화면 "최초 수집 · 성역" 카드.** 이미 "이 값은 어떤 편집으로도 바뀌지 않아요"라고 선언하는 자리 → 불변 원본 음성이 개념적으로 정확히 여기 속함.
- 해당 `item.id`의 음성이 `AudioStore`에 존재하면 **[다시 듣기]** 노출. 작은 `AVAudioPlayer` 래퍼(재생/일시정지/진행).
- **중요도:** 녹음이 제대로 됐는지 **검증 수단**이자, 나중 ⑥("원문 편집")에서 **음성 들으며 텍스트 고치기의 토대**.

## 5. 불변성 · 생명주기

- **캡처 중:** 임시 파일(`tmp/capture-<sessionId>.m4a`)에 모든 take append(§2).
- **[저장]:** 항목 UUID 생성 → 임시 파일을 `audio/<uuid>.m4a`로 **이동(rename)** → create에 `audio:` 필드. **이동 후 파일은 다시 열지 않음 = write-once·불변.**
- **[취소]/discard/시트 종료(미저장):** 임시 파일 **삭제**.
- **항목 삭제(tombstone):** 복구 가능하므로 **음성 파일 보존**(삭제하지 않음). 고아/영구정리는 나중 과제(현재 영구삭제 자체 없음).
- 음성 확정 실패(이동 실패 등)여도 항목은 **음성 없이** 정상 생성(graceful).

## 6. 엔진·병합 무변경 (불가침 확인)

- **`MergeEngine`(병합 로직) · `EventLog`(파싱) · `merge-design.md` = 완전 무변경.**
- **유일한 Core 접촉:** `EventWriter`의 create-블록 화이트리스트에 **`"audio"` 1줄**(직렬화 목록, 병합 규칙 아님). 기존 이벤트(audio 없음)엔 무영향.
- macOS: STT·녹음 iOS 전용 → **Mac 텍스트 수집은 음성 없음**(무영향).

## 7. iCloud 동기화 — **구현됐다 (2026-08-20)**. 다만 모양이 예고와 다르다

> ### ⚠️ **이 절은 시제가 뒤집혔다** — 「향후 확장 … (지금 구현 안 함, 여지만)」이었다
> **됐다.** 그리고 **예고와 셋이 달라졌다.** 정본 = `docs/native/media-icloud-design.md`.

| | 2026-07 예고 | **2026-08-20 실제** |
|---|---|---|
| 시제 | 「지금 구현 안 함, 여지만」 | ⛔ **됐다** — 135개 이관 완료(00:14) |
| 무엇을 올리나 | **항목별 옵트인** — *"특정 음성만 골라"* | ⛔ **전부 올린다.** 분실 대비가 목적이라 **고를 것이 없다** |
| 어떻게 찾나 | `AudioStore`의 **`searchDirs()`에 iCloud 폴더를 더한다** | ⛔ **그 방식은 안 됐다.** iCloud 쪽은 **보안 스코프를 열어야** 보이고 **자리(하위 폴더/루트)를 먼저 계산**해야 해서 **URL 목록에 안 담긴다** → 찾기를 **세 갈래**로 갈랐다(`media-icloud-design.md` §4) |
| 동기화 여부를 별도 필드로 | 나중에(예: `set audiosync=icloud`) | ⛔ **안 썼고 필요 없어졌다** — 전부 올리므로 켜고 끌 상태가 없다 |
| **불변 포인터와 가변 위치 분리** | 그렇게 하겠다 | ✅ **유지됐다.** `audio: <uuid>.m4a`(create·불변·**정체성**)는 **한 글자도 안 건드렸고 자리만 바뀌었다** |
| `AudioStore`가 저장 위치를 추상화 | 그렇게 하겠다 | ✅ **유지됐다** — 호출부(재생·존재확인)는 그대로다 |
| 엔진·병합 | 무영향 | ✅ **무영향** |

> ### ★ 무엇이 값을 했나
> **파일명=UUID · `AudioStore` 추상화 · create 포인터=정체성** — 셋을 **그대로 두고** 자리만 바꿔서
> iCloud를 받아냈다. **뒤집힌 것은 「무엇을·어떻게 찾나」이고, 유지된 것은 「무엇이 정체성인가」다.**
