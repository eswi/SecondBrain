# 실기기 검증 체크리스트 — 시각(시·분) 도입 (Stage 1·2, 2026-08-02)

> 목적: 시각 도입(방식 a, 날짜 칸 값 형식 확장)이 실기기에서 그대로 동작하는지 확인.
> 설계 정본 = `recurrence-design.md` §6-A/§6-B. 코드 근거 = 커밋 `df85846`(Stage 1 엔진) · `d938b52`(Stage 2 UI).
> 헤드리스로 갈 수 있는 데까지 갔다(코어 테스트 130, 시각 14건 · iOS 빌드 OK) — 여기 목록은 **화면·알림·실데이터**라 헤드리스로 못 보는 것만.
> 설치·서명·주의사항은 `iphone-verify-checklist.md` A·F·G절. 각 항목 `확인:` 칸에 날짜·기기·경로 적고 통과면 `- [ ]`→`- [x]`.

## 준비 (테스트 데이터는 만들지 않는다)
- 기존 실데이터 항목 중 **마감/미리 알림이 미래인 것**으로 확인한다(예: 「이사 계획」 마감 08-03, 「T 우주」 마감 08-07).
- 시각을 새로 넣어보는 건 실제로 쓸 항목에 넣는다(약·회의 등). 안 쓸 값은 넣지 않는다.

## A. 입력 — "시각" 토글

- [x] **A-1. 시각 안 넣을 자유(기본).** 상세에서 날짜만 정하고 "시각" 토글 **OFF** 유지 → 저장 → 파일 값이 `YYYY-MM-DD`(**T 없음**).
      "날짜 설정" 버튼으로 잡은 것도 날짜만.
      `확인: 2026-08-02 · iPhone 16 Pro · 경로: 상세 시간 설정, 토글 OFF로 날짜만 저장 확인(사용자 "2번")`
- [x] **A-2. 시각 넣기 + 조용한 강등 없음.** 토글 **ON** → 시·분 피커 등장(기본 09:00) → 시각 조정 → 저장 → 재열람 시 그 시각 유지.
      **시각 넣은 항목이 목록에서 안 사라짐**(게시·D-day 그대로 = 조용한 강등 없음).
      `확인: 2026-08-02 · iPhone 16 Pro · 경로: 상세에서 시각 지정·저장·재열람, 목록 유지 확인(사용자 "1번")`
- [ ] **A-3. 옛 date-only 항목.** 시각 없던 기존 항목을 열면 토글 **OFF**로 열리고, 그대로 편집된다(강등·값 변형 없음).
      `확인: ____-__-__ · 기기 ______ · 경로 ______`
- [ ] **A-4. 날짜 바꿔도 시각 보존.** 시각 있는 항목의 **날짜만** 피커로 바꿔도 시각이 유지된다(날짜만 갈림).
      `확인: ____-__-__ · 기기 ______ · 경로 ______`
- [ ] **A-5. 시각 껐다 켜기.** 토글 ON→OFF면 값이 date-only로 돌아가고(시각 제거), OFF→ON이면 09:00으로 다시 붙는다.
      `확인: ____-__-__ · 기기 ______ · 경로 ______`

## B. 표시

- [ ] **B-1. 목록 캡션에 시각 (재오픈 — 캡션 잘림 수정 후).** *(수정: 지금 챙길 것 목록 캡션에서 **수집 시각 제거**(상세 "최초 수집"에 남음) + **연도 생략**(올해면 `08-05`, 다른 해면 `2027-08-05`).)*
      **미리 알림 시각이 목록 캡션에 잘리지 않고 보인다**(예: `~08-05 19:00 · ↻08-03 08:00`). 보관함·검색은 수집 시각 유지.
      `확인: ____-__-__ · 기기 ______ · 경로 ______`
- [x] **B-2. 오른쪽 시각 칩 (마감 기준).** *(fc9c0da: 캡션 잘림 → 오른쪽 배지 아래 칩. 칩은 **마감 기준만** — D-day 세분.)*
      **마감에 시각 있는** 항목만: 오늘=`N시간 남음`/`지남`, 다른 날=마감 `HH:mm`. **마감 없으면(미리 알림만) 칩 없음**(카운트다운은 기한이 있어야 성립 — 사용자 지적).
      `확인: 2026-08-02 · iPhone 16 Pro · 오른쪽 칩·"N시간 남음" 확인(사용자). 마감 없으면 칩 안 뜸도 확인.`

## C. 미루기 (§6-B 결정 3)

- [x] **C-1·C-2. 미루기 시각 보존.** 시각 있는 미리 알림을 +7일 미루기(목록 스와이프·상세) → **시각 유지**(날짜만 밀림).
      `확인: 2026-08-02 · iPhone 16 Pro · 사용자 "모두 확인했음"`
- [x] **C-3. 규칙1 유지.** 시각 있는 값에서도 미리 알림 ≤ 마감−1일이 date-only 때와 동일.
      `확인: 2026-08-02 · iPhone 16 Pro · 사용자 "모두 확인했음"`

## D. 알림 (§6-B 결정 2·§6-A)

- [ ] **D-1. 시각 알림 (재오픈 2026-08-02).** 시각 있는 항목의 알림이 **그 시각**에 온다(9시 아님).
      *(재오픈 이유: 앞서 "모두 확인"은 실제로 미리 알림에 시각을 걸어본 게 아니었다 — 주차 항목에 다시 보기 날짜가 없어 토글이 안 떠서. 코드상 가능함은 확인됨(ClassSpec 주차=resurface 씀, timeRow가 양쪽에 시각 토글). 실제로 걸어 받아보고 닫는다.)*
      ⚠️ **알림은 publishDay(미리 알림 우선, 없으면 마감) 기준.**
      **경로 A — 미리 알림 시각(주차/약 등):** 상세 → 다시 보기 **"날짜 설정"(→ 오늘)** → **그때 뜨는 "시각" 토글 ON** → 시각 = 지금+2~3분 → 저장 → 배너.
      **경로 B — 마감 시각(할 일):** 마감 = 오늘 + 지금+2~3분, 미리 알림 없음 → 배너 + D-DAY·칩 일관(규칙1 회피).
      편집 즉시 재예약(`InboxModel.load()`→`scheduleNotifications()`). 안 오면 알림 권한 확인.
      `확인: ____-__-__ · 기기 ______ · 경로 ______`
- [x] **D-2. 시각 없는 항목 = 9시 폴백.** date-only 항목은 여전히 오전 9시에 온다(기존 동작 보존).
      `확인: 2026-08-02 · iPhone 16 Pro · 사용자 "모두 확인했음"`
- [ ] **D-3. (선택) 자정.** `T00:00`으로 고른 항목은 **자정**에 온다(시각 없음과 다르다). 굳이 만들 필요는 없고, 자연히 생기면 확인.
      `확인: ____-__-__ · 기기 ______ · 경로 ______`

## 미결 (기록만 — 지금 안 고침)

- **발견성 — "날짜 설정 → 그다음 시각 토글" 순서.** 날짜가 없는 줄엔 시각 토글이 안 뜬다(`DetailView` `timeRow`의 `if hasDate`). **맞는 동작**이지만, 새 항목에서 시각을 넣으려 하면 **넣을 자리가 없는 것처럼 읽힌다**(실제로 그렇게 읽혔다 — 주차 항목 알림 시험 때). 사람이 "날짜부터 잡아야 시각이 열린다"를 알아야 한다. 개선 후보(나중): 날짜 없을 때도 시각을 바로 걸 수 있게 발견성 높이기. → `recurrence-design.md` §6-B에도 같은 미결.

## 문제 생기면 메모할 것
- 어느 항목이 어떻게 달랐는지 **본 것을 그대로**. 실데이터인지 SampleData인지 구분.
- 특히 **"조용한 강등"**(시각 넣었더니 항목이 목록·알림에서 빠짐)이 보이면 즉시 적을 것 — 이게 이 설계의 핵심 실패 양상이다(헤드리스 테스트로 막았지만 실기기 재확인).
